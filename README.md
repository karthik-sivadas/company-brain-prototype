# Company Brain

One place where company knowledge lives, that can be **queried to get work done**, and that
anyone can extend by editing a folder.

Built by composing two tools instead of writing a platform:

| Layer | Tool | Why |
|---|---|---|
| **Extraction** | [`pm`](https://github.com/polymetrics-ai/cli) | 557 built-in connectors, incremental cursors, dedup, tombstones, run ledger, approval-gated writes |
| **Reasoning** | [`omp`](https://omp.sh) | agent loop, tool use, sessions, subagents, and skill discovery from a folder |
| **Query** | `duckdb` | reads pm's Parquet warehouse in place — no import step |
| **Knowledge** | `brain/` | skills, docs and captured answers as plain Markdown |

There is no bespoke agent runtime, no vector database and no application server.

## Quick start

```bash
bun run brain doctor      # check prerequisites
bun run brain setup       # build pm, init the project, install skills, create connections
bun run brain sync        # extract into the warehouse
bun run brain ask "how many issues are synced, and the 3 newest?"
```

## How it fits together

```
sources ──▶ pm ──▶ data/pm/.polymetrics/warehouse/**/tables/*.parquet
                                    │
                    brain/skills/  ─┼─▶ omp ──▶ cited answer
                    brain/docs/     │
                    brain/memory/   │
                        (.omp/skills is a symlink to brain/skills)
```

**pm** runs offline on a schedule and owns everything hard about sync: what changed since last
time, deduplication by primary key, deletions, and a per-run ledger. **omp** answers questions by
reading `brain/skills/` and querying the warehouse with DuckDB. Retrieval is agentic — grep and
SQL over a modest corpus — rather than an embedding index, which is a later optimisation.

## The folder is the product

```
brain/
  skills/          how-to knowledge; omp discovers these automatically
    brain-search/  where the data is and how to query it (regenerated on each sync)
    brain-setup/   how to add a source, install skills, repair the brain
    pm-*/          generated by `pm skills generate` — one per connector
  docs/            SOPs and policies (Markdown)
  memory/facts/    answers captured from people
  agents/          personas
  .skills-catalog/ the other 549 connector skills, parked out of the agent's context
```

`pm skills generate` emits **564** skills. Their descriptions are what an agent loads at startup,
so only an allow-list (`activeSkills` in `brain.config.json`) stays in `brain/skills/`; the rest are
parked. That is what `bun run brain skills` does.

## Adding a data source

Add an entry to `brain.config.json` and re-run setup:

```json
{
  "connector": "slack",
  "credential": "slack",
  "config": {},
  "fromEnv": { "access_token": "SLACK_BOT_TOKEN" },
  "streams": [
    { "name": "channel_messages", "primaryKey": "ts", "cursor": "ts",
      "table": "slack_messages", "syncMode": "full_refresh_overwrite" }
  ]
}
```

Secrets only ever appear as `fromEnv` mappings — pm reads the value from the environment, so no
token is written to config, logs or the warehouse.

Or just ask: `bun run brain ask "add Slack as a source"` — the `brain-setup` skill teaches omp the
procedure, and it will check the connector's real schema before answering.

## Verified working

- `pm` built from `polymetrics-ai/cli@main` — **557 executable connectors**
- GitHub ETL: 46 real issues → Parquet with typed columns, queried by DuckDB
- omp answers from the warehouse **and** from `brain/docs/`, citing its source each time
- omp used `brain-setup` to plan a Slack integration, correcting the skill's generic example
  after inspecting the installed connector's actual schema

## Commands

| Command | Purpose |
|---|---|
| `bun run brain doctor` | check `omp`, `duckdb`, `go`, `git`, pm binary, project, skill link |
| `bun run brain build-pm` | clone and compile pm (needs Go; CGO is required by the DuckDB driver) |
| `bun run brain setup` | idempotent bootstrap |
| `bun run brain skills` | regenerate and transport skills |
| `bun run brain sync [connector]` | extract |
| `bun run brain tables` | list queryable Parquet tables |
| `bun run brain ask "…"` | ask a question |

## Notes

- `pm` creates `.polymetrics/` in its working directory, so every invocation is pinned to `data/pm/`.
- A sync reporting `failed` with `page budget` in the error is expected when `max_pages` is set —
  the rows are committed. Use `"max_pages": "all"` for a complete pull.
- Public GitHub access needs both `auth_type=public` and `rate_limit_ip`.
- `omp` blocks on `readPipedInput` unless stdin is closed; the CLI handles this.
